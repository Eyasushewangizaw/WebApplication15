# Core MVC Web Application - README
### Project Overview
This ASP.NET Core MVC web application provides comprehensive CRUD (Create, Read, Update) functionality for managing a relational database with multiple interconnected business entities. The project follows the Model-View-Controller architectural pattern and includes a complete set of features for handling categories, customers, employees, orders, order details, products, shippers, and suppliers through a centralized data access layer.

### Architecture and Structure
The application is organized following standard MVC conventions with a HomeController that handles HTTP requests and coordinates between the models and views. The Models folder contains entity classes representing each database table including Categories.cs, Customers.cs, Employees.cs, Orders.cs, OrderDetails.cs, Products.cs, Shippers.cs, and Suppliers.cs, along with DBGateway.cs for data access operations, DB_connection.cs for database connectivity management, and ErrorViewModel.cs for standardized error handling. The Views folder is structured under Home with separate subfolders for different operation types, featuring read-only views for displaying data (GetCategories.cshtml, GetCustomers.cshtml, GetEmployee.cshtml, GetOrderDetails.cshtml, GetOrders.cshtml, GetProducts.cshtml, GetShippers.cshtml, GetSuppliers.cshtml), insertion forms for creating new records (InsertACategoryForm.cshtml, InsertAPProductForm.cshtml, InsertCustomerForm.cshtml, InsertEmployeeForm.razor, InsertOrderDetailsForm.cshtml, InsertOrderForm.cshtml, InsertShipperForm.cshtml, InsertSuppliersForm.cshtml), update forms for modifying existing records (UpdateACategoryForm.cshtml, UpdateACustomerForm.cshtml, UpdateAProductForm.cshtml, UpdateASupplierForm.cshtml, UpdateAnEmployeeForm.cshtml, UpdateAnOrderDetailsForm.cshtml, UpdateOrderForm.cshtml, UpdateShipperForm.cshtml), and additional views like Privacy.cshtml and the home page Index.cshtml, with launch configuration managed through the Properties/launchSettings.json file.

### Database Relationships and Features
The application manages a complex relational database schema where Categories serve as parents to Products, Products link to both Categories and Suppliers, Suppliers are parents to Products, Customers, Employees, and Shippers all connect to Orders, and OrderDetails establish the many-to-many relationship between Orders and Products. This structure enables complete data management across all business entities with consistent user interface design for all CRUD operations, centralized database operations through the DBGateway data access layer, and proper handling of complex relational data integrity throughout the application.

### Setup and Configuration
To set up the application, ensure you have the appropriate .NET Core SDK installed along with SQL Server or a compatible database system, preferably using Visual Studio 2022 or later for development. Begin by cloning or downloading the project files, opening the solution in Visual Studio, configuring the database connection string in DB_connection.cs (typically formatted as "Server=YOUR_SERVER;Database=YOUR_DATABASE;Trusted_Connection=True;"), running the necessary database scripts to create the required tables, building the solution to restore NuGet packages, and finally running the application to begin managing your data. The application provides an intuitive navigation flow starting from the home page where users can access different entity management sections, view existing records through the GET views, add new records using the insertion forms, and modify existing data through the update forms.

### Technology Stack and Development Guidelines
Built with ASP.NET Core MVC and C#, the application utilizes ADO.NET or Entity Framework through the DBGateway pattern for data access, HTML and Razor views for the user interface with one Razor component (InsertEmployeeForm.razor), Bootstrap for responsive styling, and SQL Server for database management. When contributing to the project, developers should follow the established MVC pattern by adding new models in the Models folder, creating corresponding controllers in the Controllers folder, placing views in the appropriate Views/Home subfolder, and updating the DBGateway class to include any new data access methods. The project emphasizes proper error handling through the ErrorViewModel and maintains consistent coding standards throughout the codebase.
